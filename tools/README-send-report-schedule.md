# รอบส่งอีเมลอัตโนมัติ — ทำไมไม่ส่ง และตั้งให้ส่งอย่างไร

## ระบบนี้ไม่มีตัวจับเวลาอยู่ในเว็บ

หน้า **Report emails** ทำได้แค่สองอย่าง: เก็บว่าใครจะได้รับ วันที่/เวลาเท่าไร
และปุ่ม **ส่งเดี๋ยวนี้** ที่ส่งทันทีตอนกด

คนที่ส่งตาม "รอบ" จริง ๆ คือ console app:

```
KpiReport.Etl.exe send-report
```

ถ้าไม่มีใครรันคำสั่งนี้ วัน/เวลาที่ตั้งไว้ในหน้าเว็บจะไม่มีผลเลย — ไม่ใช่บั๊ก
แต่เป็นการออกแบบ เพราะ IIS application pool มี idle timeout และ recycle ตัวเอง
งานตามตารางที่ฝากไว้ในเว็บจึงไม่รับประกันว่าจะได้รัน

## ตั้งครั้งเดียวด้วย Task Scheduler

รันในฐานะ **บัญชีเดียวกับที่ตั้ง `KPI_SMTP_PASSWORD` ไว้** (environment variable
ระดับผู้ใช้เป็นของแต่ละบัญชี ถ้าตั้งคนละบัญชี task จะส่งไม่ออกและขึ้น error
ว่าไม่พบ `KPI_SMTP_PASSWORD`) และเปิด command prompt แบบ Run as administrator:

```bat
tools\register-send-report-task.cmd
```

ได้ task ชื่อ `KPI Monthly Report - send` ที่รัน `tools\send-report.cmd` **ทุกชั่วโมง**

ตั้งรายชั่วโมงคำสั่งเดียวพอ ไม่ต้องตั้งรายเดือนตามผู้รับแต่ละคน เพราะวัน/เวลา
ของแต่ละคนอยู่ในฐานข้อมูล (แก้จากหน้าเว็บได้) และตัวโปรแกรมเป็นคนตัดสินเอง
ว่ารอบนี้ถึงกำหนดของใครแล้ว ส่วนการกันส่งซ้ำอาศัย `meta.ReportDeliveryLog`
อีกชั้นหนึ่ง — เครื่องปิดอยู่ตอน 08:00 ก็ยังได้รับตอนเปิดเครื่องรอบถัดไป
ไม่ตกรอบทั้งเดือน

คำสั่งที่ใช้บ่อย:

```bat
schtasks /query  /tn "KPI Monthly Report - send" /v /fo list   ดูสถานะ + Last Run Result
schtasks /run    /tn "KPI Monthly Report - send"               สั่งรันเดี๋ยวนี้
schtasks /delete /tn "KPI Monthly Report - send" /f            ยกเลิก
```

`Last Run Result` = จำนวนฉบับที่ล้มเหลว (0 = สำเร็จหมด) ตั้งแจ้งเตือนจากค่านี้ได้เลย

## ไล่ปัญหาเมื่อรอบมาแล้วไม่มีอีเมล

ไล่ตามลำดับนี้ หยุดที่ข้อแรกที่เจอ

1. **task มีอยู่จริงไหม** — `schtasks /query` ตามข้างบน ถ้าไม่มี = สาเหตุอยู่ที่นี่
2. **ลองรันมือดูก่อนว่าโปรแกรมคิดอะไร**

   ```bat
   cd src\KpiReport.Etl\KpiReport.Etl\bin\Debug
   KpiReport.Etl.exe send-report --dry-run
   ```

   ผลลัพธ์บอกรายคนว่า `ยังไม่ถึงกำหนด` / `เคยส่งเดือนนี้ไปแล้ว` /
   `ไม่มีข้อมูล KPI ของเดือนนี้` / จะส่งจริง
3. **ยังไม่มีเดือนที่มีข้อมูล** — ถ้าขึ้นว่าไม่มีเดือนใน `rpt.vw_ValidMonth`
   ให้รัน `KpiReport.Etl.exe run-all` แล้ว `rollup` ก่อน
4. **เคยส่งเดือนนี้ไปแล้ว** — รอบอัตโนมัติส่งเดือนละฉบับต่อผู้รับ ดูได้จาก
   หน้า **log การส่งทั้งหมด** ในเว็บ ถ้าต้องการส่งซ้ำจริง ๆ ใช้ `--force`
5. **ผู้รับถูกกรองออก** — `meta.vw_ActiveReportSubscription` ตัดผู้รับที่
   `IsActive = 0` และผู้รับที่ผูกกับบัญชีที่ถูกล็อกออกทั้งหมด หน้าเว็บจะขึ้น
   ป้าย "ระงับ" พร้อมเหตุผลให้
6. **ส่งแล้วแต่ไม่ถึงกล่องจดหมาย** — ดู `tools\logs\send-report.log` และคอลัมน์
   สถานะในหน้า log: `ล้มเหลว` จะมีข้อความ error ของ SMTP ติดมาด้วย
   ส่วน `ค้าง` หมายถึงโปรเซสตายก่อนบันทึกผล
   ถ้า `Smtp.DeliveryMethod` ยังเป็น `SpecifiedPickupDirectory` อีเมลจะไม่ออกจาก
   เครื่องเลย แต่จะเป็นไฟล์ `.eml` ใน `Smtp.PickupDirectory` (โหมดเดโม)

## หมายเหตุเรื่อง path

`send-report.cmd` ชี้ไปที่ `bin\Debug` เพราะเป็น build ที่ใช้อยู่ตอนพัฒนา
เวลาขึ้นเครื่องจริงให้แก้ `EXE_DIR` ในไฟล์นั้นเป็น `bin\Release`
หรือโฟลเดอร์ที่ deploy ไว้
